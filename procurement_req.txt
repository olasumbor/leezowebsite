
LEEZOFood NG.Export — Procurement WorkflowBackend Development RequirementsImportant distinction: The workflow must distinguish between viewing existing procurements from the Dashboard and creating a new procurement request from the Homepage. The Dashboard is not used to initiate a new procurement request.1. Account Creation &amp; LoginHomepage → Sign In / Register → Create Account → Login → DashboardAfter successful authentication, the user is taken to their Dashboard. The backend must maintain the authenticated user session/token and use it to identify the user for account-specific data.2. Dashboard — View Existing ProcurementsThe Dashboard does not allow the user to create a new procurement request.Dashboard → View My Procurement → Procurement History → View → Procurement DetailsProcurement History retrieves the user's procurement records from the backend.Display Procurement ID, Date, Status, and View/Action.Clicking View opens the corresponding Procurement Details page.The details page must display the correct procurement associated with that Procurement ID.3. Creating a New ProcurementA new procurement request is NOT initiated from the Dashboard or Procurement History. The user creates a new procurement through the Procurement link on the main website homepage.Homepage → Procurement → Procurement Form → Enter Information → Submit Request → Backend Receives Request → Backend Saves Request → Procurement ID Generated → Confirmation → Procurement HistoryValidate and save the submitted procurement data.Generate a unique Procurement ID for every new request.Automatically associate the request with the currently authenticated user.Make the new request appear in that user's Procurement History.Allow the user to open the request and view its Procurement Details.4. User-to-Procurement RelationshipThe backend should maintain a clear relationship between each user account and that user's procurements:User → User's Procurements → Procurement 1 / Procurement 2 / Procurement 3 / …View My Procurement must return only procurements belonging to the logged-in user.Users must not see procurements belonging to other users.Every new procurement submitted by a logged-in user must be associated with that user's account.The Procurement ID must identify the correct procurement record.5. Key RequirementThe Dashboard is for accessing and viewing the user's existing procurement records. The Homepage Procurement page is where a new procurement request is created. These are separate functions and must be implemented as separate workflows.
