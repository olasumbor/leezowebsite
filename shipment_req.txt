
LEEZOFood NG.Export — Shipment Tracking &amp; HistoryBackend Development &amp; Integration RequirementsPurpose: The frontend shipment tracking and history pages are already designed. The backend should provide the complete real-data system and API integration required to make the entire shipment workflow fully functional on the live website.1. Shipment Creation &amp; ManagementShipment records must be created and managed from the backend/admin side. The frontend must not generate official shipment records or tracking numbers.Admin creates the shipment.Backend generates/assigns a unique Shipment/Tracking ID, e.g. CAR8739020892.Admin assigns the shipment to the appropriate user/customer.Backend stores all shipment information and status history.Admin can update status, location, delivery dates, and other shipment information.2. Public Track ShipmentThe existing frontend Track Shipment page allows a user to enter a Shipment/Tracking ID. The backend must provide the API that receives the tracking ID, finds the shipment, and returns its current information.Flow: Track Shipment → Enter Tracking ID → Backend API → Find Shipment → Return Current Details → Display on Existing FrontendReturn current shipment status.Return current location/status details.Return origin and destination.Return shipment and expected delivery dates.Return relevant shipment information and tracking/progress history.If the ID does not exist, return an appropriate error so the frontend can display 'Shipment not found.'3. Logged-In User — View My ShipmentsAfter login, the user can go to Dashboard → View My Shipments → Shipment History.The backend must identify the authenticated user.Return only shipments belonging to that user.A user must not be able to access another user's shipment records by changing an ID or URL.4. Shipment HistoryThe existing Shipment History page should retrieve the user's real shipment records from the backend.The page must display these statistics:Total ShipmentsDeliveredPendingIn TransitThese statistics must be calculated from the user's actual backend shipment records and must update when shipment statuses change.5. Shipment History Table &amp; SearchThe history table should display each shipment with its Shipment ID, date, status, and View action.The user must also be able to search by Shipment ID. The backend should return the matching shipment, subject to the user's access permissions.Flow: Shipment History → Search Shipment ID → Backend → Matching Shipment → Display Result6. Shipment DetailsClicking View must open the existing Shipment Details page for that specific shipment and retrieve the latest data from the backend.Shipment/Tracking IDCurrent statusOriginDestinationCurrent locationShipment dateExpected deliveryActual delivery, when availablePackage/cargo information, where applicableShipment progress/tracking timelineIf the admin changes a shipment from Pending to In Transit, for example, the customer-facing details page must show the updated status when it requests the shipment again.7. Admin Shipment ManagementThe backend/admin system should allow authorized administrators to:Create shipmentsGenerate/assign Shipment IDsAssign shipments to usersUpdate shipment statusUpdate current locationUpdate expected delivery dateRecord actual delivery dateAdd shipment progress/history eventsCorrect shipment informationView and manage shipment records8. ResponsibilitiesBackend:Create and store shipment recordsGenerate/manage Shipment IDsAssociate shipments with usersStore current status and shipment historyUpdate shipment informationProvide shipment-search and tracking APIsProvide shipment-history data and statisticsEnforce authentication and ownership/authorizationFrontend:Track Shipment page and inputTrack Shipment buttonShipment History pageShipment statistics displayShipment search interfaceShipment history tableView buttonsShipment Details pageShipment progress/timeline display9. Critical RequirementThe backend must be the single source of truth for shipment tracking. The existing frontend sample/static shipment data is only for development/testing and must be replaced by live backend data. The final live website must allow both public tracking and authenticated users to view their own shipment history and details, while authorized administrators control shipment creation and updates.
